# RWA 시장시간 불일치와 경제적 보안 시뮬레이션

RWA(실물연계자산)를 수용한 퍼블릭 블록체인에서 **전통시장과 온체인 프로토콜의 운영시간 불일치**가 어떻게 경제적 손실로 이어질 수 있는지 분석하는 파이썬 연구 프로젝트입니다.

현재 연구의 중심은 다음 두 축입니다.

1. 토큰화 주식의 주말 가격 공백을 이용한 통합 공격 시나리오
2. 천연가스·원유 등 원자재 RWA 시나리오

## 핵심 문제의식

전통시장은 휴장하지만 온체인 대출은 계속 실행될 수 있습니다. 이때 오라클 가격, 신규 차입, 청산과 온체인 유동성 사이에 공백이 생기면 공격자는 전체 PoS 지분을 공격하지 않고도 제한된 책임 구조를 이용해 손실을 대출 프로토콜에 전가할 수 있습니다.

따라서 이 연구는 체인의 총 스테이크를 깨는 비용보다 다음 질문에 집중합니다.

```text
시장가격이 갱신되지 않는 동안 신규 차입이 가능한가?
매도보다 차입이 경제적으로 유리한가?
가격이 다시 열렸을 때 상환과 담보 포기 중 무엇이 유리한가?
부분청산 후에도 대출 프로토콜에 부실채권이 남는가?
```

## 1. 통합 Weekend Gap 시나리오

### 공격 흐름

1. 금요일 저녁 이후 미국 주식의 주요 가격발견 시장이 닫힙니다.
2. 온체인 대출 프로토콜은 계속 운영되고, 토큰화 주식 담보는 마지막 관측가격으로 평가될 수 있습니다.
3. 공격자는 얇은 온체인 풀에서 담보를 직접 매도하는 것과 담보대출을 비교합니다.
4. 폐장 중 신규 차입이 가능하고 대출액이 매도 실현액보다 크다면 대출을 선택합니다.
5. 시장 재개 후 담보가격이 충분히 하락하면 상환보다 담보 포기를 선택합니다.
6. 청산인이 부분청산을 수행한 뒤에도 회수하지 못한 금액은 프로토콜 부실채권이 됩니다.

### 두 개의 구현 계층

#### 문서 수식 재현 모델

`weekend_gap_simulation.py`는 연구 초안의 단순 수식을 그대로 확인하기 위한 결정론적 기준선입니다.

```text
원금 부실 임계: g > 1 - LTV
담보가 부채와 보너스를 감당하지 못하는 임계: g > 1 - LTV(1+b)
차입 > CPMM 매도: C0 > Y(1-LTV)/LTV
```

이 모델은 수식을 재현하지만 특정 프로토콜의 실제 동작을 증명하지 않습니다.

#### 프로토콜 인식형 모델

`weekend_gap_protocol_simulation.py`는 다음 조건을 명시적으로 검사합니다.

- 폐장 중 신규 차입 허용 여부
- 오라클 가격 신선도와 폐장 예외
- 종가 기준 가격 밴드
- Max LTV, Liquidation LTV와 Borrow Factor
- 담보 공급 캡, 부채 대출 캡과 가용 유동성
- 이용률 기반 변동금리
- close factor 기반 반복 부분청산
- 시간에 따라 변하는 청산 보너스
- 청산인의 실행비용과 담보 매도 슬리피지
- 실제 애그리게이터 견적 또는 명시적인 CPMM 준비금
- 상승과 하락을 모두 포함한 전체 가격 갭 표본

검증되지 않은 기본 설정에서는 폐장 중 신규 대출을 차단합니다. 실제 온체인 설정과 재현 가능한 데이터가 모두 입력되기 전에는 결과를 실증값으로 표시하지 않습니다.

자세한 사용법은 [`PROTOCOL_AWARE_WEEKEND_GAP.md`](PROTOCOL_AWARE_WEEKEND_GAP.md)를 참고하세요.

## 2. 원자재 RWA 시나리오

천연가스·원유 등 원자재는 주식과 다른 시장구조를 가집니다. 현물가격만으로 모델링할 수 없으며 선물 만기, 롤오버, 거래시간, 일일 휴장, 저장비용과 지역별 벤치마크를 구분해야 합니다.

현재 원자재 시나리오는 **설계 및 자료 입력 대기 단계**입니다. 구체적인 공격 경로와 대상 프로토콜이 확정되기 전에는 임의의 수식이나 수익값을 코드에 넣지 않습니다.

구현 전 확인할 항목은 [`COMMODITY_SCENARIO_PLAN.md`](COMMODITY_SCENARIO_PLAN.md)에 정리했습니다.

## 실행 방법

Python 3.10 이상을 권장하며 현재 모델은 외부 패키지 없이 실행됩니다.

문서 수식 재현 모델:

```bash
python3 weekend_gap_simulation.py
```

프로토콜 인식형 모델:

```bash
python3 weekend_gap_protocol_simulation.py
```

전체 테스트:

```bash
python3 -m unittest discover -s tests -v
```

현재 자동 테스트는 총 27개입니다.

- Weekend Gap 문서 재현 모델: 9개
- Weekend Gap 프로토콜 인식형 모델: 18개

테스트 통과는 입력된 규칙과 수식이 코드에서 일관되게 작동한다는 의미입니다. 실제 공격 가능성이나 실제 손실규모를 증명하지 않습니다.

## 실증 결과로 사용하기 위한 최소 조건

다음 자료가 모두 확보되어야 결과를 특정 프로토콜의 실증 결과로 해석할 수 있습니다.

1. 대상 마켓·자산·블록 번호가 포함된 온체인 설정 스냅샷
2. 폐장 중 신규 대출과 오라클 가격 처리 규칙
3. 실제 Max LTV, Liquidation LTV, Borrow Factor와 각종 캡
4. 이용률별 차입금리 곡선
5. close factor와 청산 보너스 상승식
6. 포지션 규모별 실제 온체인 매도 견적
7. 재현 가능한 가격 갭 원자료
8. 동결·회수·법적 상환청구 등 온체인 외부 제약

## 주의사항

- 기본값은 실제 프로토콜의 최신 수치가 아니라 검증 전 연구 입력값입니다.
- `empirically_calibrated=False`인 결과를 실제 공격 가능성의 증거로 사용하면 안 됩니다.
- 공개 저장소에는 개인 인증정보, API 키, 지갑 비밀키 또는 개인 식별자료를 저장하지 않습니다.
- 본 코드는 연구 목적이며 금융·투자 또는 실제 공격 실행을 위한 지침이 아닙니다.
